# Stage 2 — Live panels + news

> Part of the [Home landing page epic](00-epic.md). Goal: the "alive" layer on top of the stage-1
> shell — Pulse, the What's-new authored-news feature, and the infrastructure each one drags
> in, landed exactly when first needed (admin access arrives with news authoring, visit tracking
> arrives with the new-since-last-visit line).

## Outcome

Home stops being a static ranking and starts showing *now*: who's online, what's live, and a
channel for Matt to talk to users with rich, eye-catching announcements — without redeploying to
edit one.

## Design (settled 2026-08-28 — contract in [design-mock.html](design-mock.html))

**Pulse is a line, not a region — a dimmer, not a switch.** Form (revised 2026-08-29): a
**full-width divider directly beneath the hero**. The breathing gold dot is **clamped hard
left** — it is the pulse *source* — and events **emit from it as a ticker**: each event is a
discrete quiet pill; a new one slides in beside the dot while older pills visibly slide right
and dim with age; the oldest drops off. Cap is **width-aware** (as many as fit, max 4), not a
fixed count. A hairline rule trails from the last pill to the
page edge, so the line owns a sliver of space even when quiet. Avatar coins sit between dot
and items.

**No modes (corrected 2026-08-29): busy-ness is a continuous dial.** The weighted activity
score interpolates breath rate (~4s at rest → ~0.9s flat out), coin count, and event cadence —
there are no discrete states, only momentum from quiet to busy. At the calm end, the lone pill
is serene and forward-pointing ("All quiet in the tavern · next game Thursday, 20:00") — calm
is championed and never reads as dead, because it always names the next heartbeat. As the
room warms (players logging in, editing characters, writing notes before start), the dial
simply rises.

**A live session is content, not a mode.** It appears as a **sticky gold pill at the head of
the line** ("Coriolis is live · 3 at the table") carrying its own **Join** action, and it
raises the activity floor — but the ticker keeps flowing behind it. The pulse never stops or
changes behaviour because a game is live; it just runs hotter.

**Weighted intensity (Matt, 2026-08-28)**: what raises the pulse is weighted, not counted —
a user in-session awaiting players weighs most; online and *doing something* pre-session
(editing their character, writing notes) weighs more than idling on the dashboard; merely
logged in weighs least; a scheduled session drawing near raises the baseline. Design the
weight table up front; v1 feeds it the signals that exist (online, in-session) and richer
context signals join as they become available.

Standing constraints: every item actionable (a friend is a hook to the social panel; a live
game gets Join); anything sharing a user's own activity with friends (e.g. "{user} is playing
{track}") must be visible and opt-out-able; the news modal look is settled in the mock.

## PR sketch

### PR 1 — Admin infra + news backend
- **Admin access** (first feature to need it): `ADMIN_EMAILS` in the runtime env files
  (`dev.env`/`prod.env`, documented in `env.example`) + a `require_admin` dependency in
  `shared/dependencies/` that runs after `get_current_user_from_token` and compares the resolved
  user's email against the allowlist. No DB role column, no admin claim in the JWT (tokens
  outlive revocation via refresh) — the check is per-request, server-side.
  **Ground truth (audit 2026-08-29)**: NO admin concept exists anywhere today — no role
  column on `users`, no dependency, no allowlist, no admin router; `admin.py` is a
  shell-gated Click CLI by explicit design. Greenfield as assumed
  ([dependency-audit.md](dependency-audit.md) §5).
- **News module** `modules/news/`, standard aggregate-centric layout (api / application / domain /
  model / repositories / dependencies). `news_posts`: id, title, hero image (library asset ref
  or S3 key — decide with the image question below), TipTap document (JSONB), published_at,
  author_id, draft/published flag. Autogenerated Alembic migration; import the model in
  `alembic/env.py`.
- Endpoints: reads for any authenticated user; writes behind `require_admin`.
- **Likes + read state** (design settled 2026-08-29 in the mock): the like counter IS the
  CTA — shows the value, click toggles ±1, heart fills when liked, beside the date →
  `news_post_likes` join table + toggle endpoint (count public, liked-state per user). The
  **NEW! flair** lives in the UPDATES *section header* (not the date line — banner art
  drowns in-card chips) and needs a per-user read receipt, flipped when the modal opens —
  a minimal slice of PR 4's tracking pulled forward (read receipt per post, or
  `last_read_news_at` on the user). Audit: no likes/reactions table and no read tracking
  of any kind exists today (nearest neighbours: `media_assets.favorite` — a private
  owner-only star — and `notifications.read`, a per-row bool).
- **NGINX**: new `/api/news` location blocks in BOTH `docker/dev/nginx/nginx.conf` and
  `docker/prod/nginx/nginx.conf` → api-site.
- This does NOT reintroduce the removed patch-notes feature: authored editorial content in
  PostgreSQL, unrelated to releases. Release notes remain GitHub Releases.

### PR 2 — News authoring + What's-new on Home
- Authoring UI reusing the existing TipTap v3 setup from notes (same extension family).
  **Open:** images inside content — `@tiptap/extension-image` (same vendor, no new third party)
  + the existing S3 presigned-URL upload flow. Decide whether v1 ships text-only or with images.
- Authoring surface gated on admin (route hidden for non-admins, enforced server-side
  regardless).
- Home card: the **noticeboard** — the page's single LIGHT card (parchment on a page of dark
  cards; contrast inversion is the "pop", not animation), with **frame-breaking art**: the
  illustration overlaps the card boundary. That breakout layer is mascot-ready — when Tabletop
  Tavern mascots exist, they live around/on the card, not trapped inside it. **Realized
  2026-08-29**: per-post optional TOP and BOTTOM banner slots, full-card-width, art contract
  21:9 (letterbox never crop), truly overflowing the card edges; READ MORE always above the
  bottom banner; the first mascot art exists (`banner-*.png` beside the mock). One card,
  dated — never a feed. If the latest post is stale, staleness is visible by design; that pressure is
  accepted.
- Click → full-screen Headless UI Modal rendering the TipTap doc read-only.

### PR 3 — Pulse
- Content: **friends online** (already served — friendship endpoints return `is_online` from the
  events WebSocket manager) + **your campaigns' live sessions** (PostgreSQL query; overlap rule:
  the hero owns your top campaign's state, Pulse owns the view across ALL your campaigns).
  Privacy boundary: only sessions the user is a member of, ever.
- **Ground truth (audit 2026-08-29 — constraints the pulse design must respect;
  [dependency-audit.md](dependency-audit.md) §4):**
  - `is_online` is BINARY, computed on-read from an in-process WS registry, exposed only
    on `GET /api/friendships/`, and never broadcast — no presence event type exists; the
    frontend learns presence only by refetching. In-memory: lost on api-site restart, not
    shared across replicas.
  - The events system is strictly per-recipient unicast with SILENT DROP when the
    recipient is offline — no fanout/topic primitive exists. A pulse feed therefore needs
    polling or new broadcast infrastructure; it cannot ride the current event system as-is.
  - The `/ws/events` inbound loop accepts ONLY `ping` — clients have no channel to report
    activity, so the weighted dial's richer signals ("editing their character", "writing
    notes") need transport as well as definition.
  - "All live sessions across my campaigns" has no single query — composable only as N+1
    (`get_by_member_id` → `get_active_session_for_campaign` per campaign);
    `get_active_sessions()` is global/unscoped. `sessions.status` is unindexed.
  - Live seat counts exist only in api-game's in-memory room state (`lobby_update` over
    the game socket); `GET /game/{room_id}` exposes seats but requires knowing
    `active_game_id`, has no index route, and api-game HTTP is unauthenticated. Matt's
    sketch (2026-08-29, parked for scoping): a campaign-level `active_session_members`
    column patched from api-game.
- The dimmer states + weighted intensity per the design section above; murmur rotation, coin
  pop-in, breath-rate ramp per the mock. Items actionable (Join / open social panel).
- Liveness: decide polling vs piggybacking the existing `/ws/events` connection — prefer
  whichever the social panel already does; don't build new transport for this first cut.
- **Part of Pulse but not this PR:** the now-playing music line ("{user} is playing {track}")
  — it needs an api-site→api-game hot-state read; extract it as its own PR when that plumbing
  is designed.
- **Never:** sessions the user isn't a member of (rejected outright as a privacy violation,
  2026-08-28) and the in-game fan-out activity feed (retired `TODO-social-live-pulse.md`).
  Pulse stays site-level and member-scoped.

## Acceptance

- Matt can write, edit, and publish a rich news post from the app as an admin-allowlisted user,
  with no redeploy; a non-admin gets 403 on write endpoints even with a hand-crafted request.
- Home shows the latest post as a card; the modal renders the rich content faithfully.
- Pulse shows a live friend + a live game with working actions, and reads as intentional when
  everything is quiet.
- No admin concept, read tracking, or Market UI exists anywhere before the PR that needs it.
